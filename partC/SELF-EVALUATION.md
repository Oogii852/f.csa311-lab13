# SELF-EVALUATION.md

## 1. Хэрэв шалгалт өнөөдөр болбол би энэ кодыг өөрөө бичиж чадах уу?

**Хэсэгчлэн** — тайлбартай:

### Чадах зүйлс:
- **Express route handler** — pattern нь тогтмол, олон давталтаар цээжилсэн
- **SQLite параметрт query** — `db.prepare().get()` хэлбэр ойлгомжтой
- **Zod validation schema** — `z.object()`, `z.string().min()` гэх мэт API ойлгомжтой
- **Jest тест бүтэц** — `describe`, `it`, `beforeEach`, `expect` ашиглах

### Хэцүү байх зүйлс:
- **ISBN checksum алгоритм** — AI-ийн буруу хувилбарыг засах явцад сурсан,
  гэхдээ шалгалтад цаасан дээр нэн даруй бичихэд алдаа гаргаж болзошгүй
- **Transaction syntax** — `db.transaction(() => { ... })()` хэлбэрийг
  баримтжуулалтгүйгээр мартаж болно
- **Swagger JSDoc тэмдэглэгээ** — `@openapi` тэмдэглэгээний яг синтаксийг
  баримтжуулалтгүйгээр буруу бичиж болно
- **TypeScript generic буцах утга** — `db.prepare().get() as IBook | undefined`
  cast хэдийд хэрэгтэйг мартаж болно

### Дүгнэлт:
Системийн архитектур, логик, data flow-г бүрэн ойлгосон. Гэхдээ зарим
library-specific syntax-ийг баримтжуулалтгүйгээр нэн даруй бичих нь хэцүү.
"AI байхгүй шалгалт"-д 70% кодыг өөрөө бичиж чадна гэж үнэлж байна.

## 2. Дахин хийнэ гэвэл юуг өөрөөр хийх вэ?

### 1. Эхнээс тест-д анхаарах (TDD)
Энэ удаад код бичиж → тест бичсэн. Дараагийн удаад тест эхлээд бичнэ.
TDD нь AI-тай ажиллахад онцгой тохиромжтой — "энэ тест pass болтол код бич"
гэж AI-д хэлэхэд илүү нарийн, зөв код гаргадаг.

### 2. AI session-ыг богино байлгах
Урт session дотор AI context алдаж, зөрчилдөх код санал болгосон тохиолдол
гарсан. 1 session = 1 тодорхой асуудал гэсэн дүрэм баримтлана.

### 3. Hallucination шалгалтыг эрт хийх
ISBN алгоритмын алдааг хожуу олсон. Цаашид mathematical / algorithm код-д
нэн даруй unit test бичиж баталгаажуулна.

### 4. `.env` тохиргоо эхнээс нэмэх
`PORT`, `DB_PATH`-г hardcode хийхгүйгээр эхнээс `.env` + `.env.example` нэмнэ.

### 5. Git commit-ийг жижиг байлгах
Зарим commit дотор хэт олон файл орсон. "1 commit = 1 логик өөрчлөлт"
гэсэн дүрмийг чандлан баримтална.

## 3. Энэ туршлагаас юу сурсан бэ?

### Техникийн сургамж

**"AI verify, don't trust"** — Энэ курсийн гол зарчим практикт батлагдсан.
ISBN алгоритм, SQLite constraint, test cleanup — гурван тохиолдолд AI алдаатай
байсан. Шалгаагүй бол production-д алдаатай код орох байсан.

**AI нь "best practice" мэддэг, контекст мэддэггүй** — Service layer санал
болгосон нь ерөнхийдөө зөв боловч манай төсөлд тохирохгүй байсан.
AI-д нөхцөл байдлыг нарийвчлан тайлбарлах нь илүү сайн хариулт авах гарц.

**Parameterized query заавал** — SQL injection эрсдэлийг AI өөрөө үүсгэсэн
код дотроос олсон нь анхааруулга болсон. Кодын review нь заавал хийгдэх ёстой.

### Workflow-ын сургамж

**CLAUDE.md үнэ цэнэтэй** — Эхний өдөр CLAUDE.md үүсгэснээр дараагийн
session-уудад AI нэг хэв маягаар код гаргасан. Convention-гүй бол хэв маяг
тогтворгүй болно.

**AI session log хэрэгтэй** — Ямар шийдвэр яагаад гарсныг тэмдэглэснээр
хожим эргэж харахад тустай болсон. "Яагаад ингэж хийсэн юм" гэсэн асуултад
хариулж чадсан.

**Кодлогч → Дизайнер/Верификатор** — Лекц 13-д хэлсэнчлэн бодит байдал
дээр батлагдсан. Цагийн 40% нь код бичих, 60% нь шалгах, ойлгох, засах
зарцуулагдсан. Энэ нь зөв.
